## 〇、先更正上一轮的两条错误结论

上一轮的 `diag_threshold_control.py` 在构造模型时写了：

```python
m.encoder = HDCPointLevelEncoder(m.dimensions, 128)   # 全新随机编码
m.models.load_state_dict(ck['models'])                # 却只加载了原型
```

**编码器没有从 checkpoint 加载**。编码器内部的 `value_hvs` / `channel_hvs` / `position_hvs`
是随机初始化的，与训练时不是同一组随机向量。用"A 编码"训练出的原型去比对"B 编码"产出的样本，
得到的相似度没有任何语义。

由这次错配得出的三条结论**全部作废**：

| 上一轮结论 | 更正 |
|---|---|
| 「通道 8 判据通过 1288」 | 错配编码下的伪结果。同源后为 **0** |
| 「阻塞点在通道 8 判据通过之后的链路」 | **推翻**。写回链路是通的（实测：predictions 非零数 == 写回矩阵非零数） |
| 「margin 是 0 → 0.02 的全灭开关」 | 在错配条件下观察所得。真实模型本来就不通过，与 margin 无关 |
| 「randomness 越大可分性越差（1639 → 24）」 | 同样基于错配编码，**该结论作废**，需在同源条件下重测 |

本次复验（`diag_encoder_source.py`，单文件 `180123_17113片段.xxc`，1799 个窗口）：

| 分组 | normal_sim 均值 | max_defect 峰值 | 判据通过 | Total Pred | P / R / F1 |
|---|---|---|---|---|---|
| A 编码随机（不同源） | 0.0005 | 0.0189 | 1288 | 1288 | 0.029 / 0.233 / 0.051 |
| **B 编码同源（真实模型）** | **0.9181** | **0.1837** | **0** | **0** | **0 / 0 / 0** |

**读法**：A 组之所以冒出 1288 个"预测"，是因为样本 HV 与原型 HV 正交（相似度 ≈ 0.0005），
判据 `md > ns` 退化成 `md > 0`，任何微小正值都算通过。这不是模型在预测，是数值噪声在触发判据。

**B 组才是真实模型的行为**：通道 8 的"正常"原型相似度均值高达 0.9181，而伤损类的峰值只有 0.1837
——`md > ns` 永远不成立。

## 一、算法原理

### 1.1 端到端管线

```
原始 JSON（探伤仪录制：BeamOffset / BeamAngle / B1 点集）
   │  ultrasonic_data_converter.UltrasonicDataConverter
   │  拼孔值 + BeamOffset 偏移
   ▼
CSV 三件套：*_hdc.csv（声程）· *_label.csv（真值）· *_predicted_label.csv（预测）
   │  encoding = original_e − BeamOffset[channel]
   │  HDCPointLevelDataset._load_data  (hdc_point_level_classifier.py:55)
   ▼
滑动窗口样本：window=128, step=1 → 形状 [128, 9]
   监督信号 = 中心行 index 63 的 9 个通道标签  (同文件:133)
   ▼
超维编码 HV ∈ R^8192  (HDCPointLevelEncoder.forward, 同文件:187)
   ▼
9 个独立分类器 × 每通道 20 类原型 → 余弦相似度
   ▼
判据 → predicted_label_0..8 → CSV / JSON → 指标 & GUI
```

### 1.2 编码器内部

`HDCPointLevelEncoder.__init__`（`hdc_point_level_classifier.py:172-185`）：

- `channel_hvs = embeddings.Random(9, 8192)` —— 9 个通道标识
- `value_hvs = embeddings.Level(256, 8192, high=256)` —— 256 级数值码本
- `position_hvs = embeddings.Random(128, 8192)` —— 128 个位置标识

`forward`（同文件:187-227）的形状变换：

| 步骤 | 操作 | 形状 |
|---|---|---|
| 输入 | 窗口切片 | `[128, 9]` |
| ① | 数值 Level 编码 | `[128, 9, 8192]` |
| ② | 与通道标识逐元素相乘 → 跨通道求和 | `[128, 8192]` |
| ③ | 与位置标识逐元素相乘 | `[128, 8192]` |
| ④ | 跨位置求和 → L2 归一化 | `[8192]` |

**一句话**：一个 128×9 = 1152 个数值的窗口，被压缩成**一个** 8192 维向量，
再拿它与每个通道各自的 20 个类原型算余弦相似度。

> 注意 `hdc_point_level_classifier.py:41` 的文档字符串写"每个窗口样本对应中心行 (index 127)"，
> 而实际常量 `CENTER_IDX = 63`（同文件:33）。注释与实现不一致。

### 1.3 判据

`HDCPointLevelModel.predict`（`hdc_point_level_classifier.py:444`）第 490 行：

```python
is_defect = (max_defect_sim > threshold) & (max_defect_sim > (normal_sim + margin))
```

- `final_pred` 默认全为 `0`（正常类），只有 `is_defect` 为真的位置才写入伤损类号（:492-493）
- 当前配置：`predict_threshold = 0.0`、`predict_margin = 0.000`
  （`config.py:80-81`；且 `config.json` 不存在，走的就是这组默认值）

## 三、结论

`Total Pred = 0` 不是单点 bug，而是**数据 → 算法 → 判据**的连锁：

```
训练数据不均衡（P1-1/P1-2）
   → 零初始化 + 跳过更新（P2-1）
   → 原型恒零（178/180 为零）
   → 判据 `md > ns + margin` 永不可满足（P2-2）
   → Total Pred = 0
```

**优先级建议**：

1. **先修 P0-1**（`_create_encoder`）——否则任何复跑都会崩，无法验证其它修复
2. **再补 P1 数据**（每通道正样本 ≥ 30 且覆盖多类）——这是 P2-1 的上游
3. **然后重构判据 P2-2**——`伤损 > 正常` 这个 margin 语义对范数不均衡的原型分类器不适用，
   建议改为 argmax + 置信度阈值，或先做原型范数均衡
4. **最后再谈编码重构 P2-3/P2-5**——注意**编码与原型必须一起重训**（P2-6）
