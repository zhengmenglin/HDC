## 0. 一句话结论

**不用 YOLO。** 用「颜色标记签名 + 位移投票 + 残差 NCC 复核」的确定性算法：
秒级、零训练、像素级定位、每一步都可溯源。原型已实现，样例跑通。

## 1. 任务本质：检索 + 定位，不是检测

"找目标图出现在哪张图的哪一段" = **单样本检索 + 区间定位**（template / signature search），
输出是"文件 + 横向区间"。
YOLO 的领域是"检测预训练类别的实例框"，目标函数都不一样——**工具选型首先要看任务，而不是先挑模型。**

## 2. 为什么不用 YOLO（三条硬理由）

| # | 理由 | 具体说明 |
|---|------|----------|
| 1 | **数据闭环矛盾** | YOLO 要成百上千张**带框标注**样本；而你手里正是"待筛选的未标注原始数据"——标注本身就要靠这个工具产出，鸡生蛋。单类单样本训 YOLO = 必然过拟合，零泛化价值。 |
| 2 | **任务粒度不匹配** | YOLO 输出"类别框"（边界回归不精细）；本任务要求"与目标图案逐标记对齐"的**像素级区间**（本例精确到 ±1px）。 |
| 3 | **实测证据：特征太弱、结构太强** | 本数据的判别信息只占 ~0.1% 像素（几根彩色标记条），而虚线/红线/背景占满幅。实测**连最直接的整图 NCC 都会假阳性**：真命中 0.922 vs 假命中 0.887（几乎追平）。YOLO 面对"目标与背景同纹理 + 极小目标"同样极难学。但我们**不需要学**：图有固定视觉语法，直接建模更快、更准、可解释。 |

> 补充：ORB/SIFT 特征匹配也不合适——虚线网格是重复纹理，特征点会满图乱配。
> 深度学习嵌入检索（CLIP 类）对"近重复渲染图"精度和可解释性都不如本方案，还要拖依赖。

## 3. 数据事实（实测，作为算法依据）

- 语料全画布 **1888×512**，同一渲染器：背景 (255,255,192)；结构行 y=113/146/189/272（虚线网）；红基线 y=397–403。
- 刻度 **285.67 px/m**，0 米位于画布中心 x=945（全幅 ±3.3m）。
- 查询图 512×512 = **以缺陷为中心**的 1:1 导出片段（紫条中心 cx=256.5，恰在画面中央），
  但**刻度被重新标注**（0.5/1/1.5，而同一位置在全画布上是 1.5/2/2.5）、"倒车长度"文字也不同。
  ⇒ **一切"渲染差异"（刻度文字、里程文字、字体抗锯齿）都不可作为匹配依据**，只比对"数据语义标记"。
- 标记调色板（实测取色）：紫 (192,0,240) 核伤主标记；砖红 (192,64,0) 螺孔/伤损点；
  绿 (0,192,0)；蓝 (0,0,240)。右侧 A..I 字母列是装饰，顶线以上的半米小标记也是装饰。

## 4. 算法（三级流水线，find_pattern.py 已实现）

```
L1 标记提取   颜色分类 → 连通域 → 抗锯齿碎片融合 → 标记表
              (类, x, y范围, 面积)；附 3 条排除规则：
              · 顶线(y≤112)上方的彩色小点 = 半米刻度装饰
              · "倒车长度"红字行带内的砖红点 = 红字抗锯齿污染
              · 右边缘≥3个成簇 = A..I 字母列（裁片图则保留）

L2 位移投票   查询图每个标记 × 语料同类标记 → 位移直方图
              （配对条件：同类 + 纵向重叠≥50% + 面积比 0.33~3）
              真正匹配 = 所有标记投同一位移（峰值）；假匹配 = 零散单票
              → 峰值即候选段，亚像素由邻域质心给出

L3 复核确认   结构抑制残差图（去背景/灰线/红字/文字带，只留彩色标记墨迹）
              的归一化相关 NCC + 覆盖率 + 未解释标记清单
```

主判据是**覆盖率**（查询图标记被"同位移、同类别、同形状"对应上的比例），
NCC 做独立第二证据。两者在本例分离度都很大（见下表）。

## 5. 实测结果（本例）

| 文件 | 位移 | 覆盖率 | 残差NCC | 覆盖区间 | 判定 |
|------|------|--------|---------|----------|------|
| **a有.png** | **+1311 px** | **4/4 = 1.00** | **0.836** | **1311~1823 px = 1.28~3.07 m** | ✅ **命中** |
| a无.png | 466 / 176 / -62 | 2/4 = 0.50 | 0.197 / 0.022 / - | — | ✗ |
| a无2.png | -16 / 42 / 106 | 2/4 = 0.50 | ≤0.161 | — | ✗ |

命中细节（a有.png，坐标系 0=画布中心）：
- 紫条（核伤标记）中心 **2.18 m**；两颗螺孔/伤损点 **2.95 m、3.06 m**；绿点 **3.04 m**
- 4 个标记的相对间距与查询图误差 ≤1.5 px（这就是它敢给"像素级区间"的底气）

对照：**整图原始像素 NCC = 0.922 / 0.887 / 0.805**——假命中几乎追平，佐证"必须标记级匹配"。

## 6. 输出与用法

```
python tools/find_pattern.py \
    --query "D:/HDC/data/核伤.../核伤....png" \
    --corpus "D:/HDC/data/2223" \
    --top 5 [--scales auto] [--min-cov 0.75] [--debug]
```

输出：
- 控制台候选表（shift / 覆盖率 / NCC / 像素区间 / 米区间）
- `result.json`（全量字段，供批量后处理）
- 复核图 `rankN_<文件>_x<位移>.png`（左=查询，右=命中段，白框=对应标记）
  + `_full.png`（全画布 + 黑框标出命中段）

## 7. 规模化与数据准备衔接

- **批量推全目录**（下一步）：可先离线把每张图的「标记表 + 标定」缓存成 JSON 索引，
  检索时只跑投票（毫秒级/图），万张级可行。
- **尺寸不同**：投票天然无关画布大小（切片=位移问题）；如查询图被缩放过，
  用 `--scales auto` 扫 0.80~1.25。
- **与打标流衔接**：命中段 px → 米 → **编码值**（x 轴语义）→ JSON/CSV 行区间 → 直接产出标注行。
  本工具已给出 px↔米 的线性标定；px↔编码 的换算系数需按渲染公式确认一次
  （B 显 JSON：编码值修正 = 编码值 + 深度·sinθ/3，见《B显JSON解析需求文档》）。
- **何时才轮到 YOLO**：当目标从"找这一个图案"升级为"找出所有核伤/所有螺孔"（类别级检测、
  不限定具体那一个）且已攒够标注时。本工具产出的标注正好是那天的训练数据。

## 8. 已知边界

- 假设竖向框架一致（同渲染器）。换软件/版本需重新校准结构行。
- 查询图标记太少（<2 个）时判据退化，建议导出时尽量带锚点。
- 极密集标记区（接头段）需按需放宽 y 容差；当前覆盖率 0.75 是保守硬阈值。
