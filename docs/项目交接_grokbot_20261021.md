## 0. 十分钟速览

**一句话**：这是钢轨超声波探伤的智能识别项目。数据是探伤仪 B 显图像（1888×512）+ 9 通道超声 A 扫数据；现在要做两件事——**用图像识别（目标检测/分类）把伤损找出来**，以及**用超维计算（HDC）做一条可对照的低资源基线**，最终写成论文。

**三件最重要的事**：

1. **路线已定：图像识别是伤损识别的主方案。** HDC 不再作为唯一主力，而是论文里的对照基线（低资源、小样本、可增量、可解释那条线）。
2. **数据准备链已经打通**：从 63 万张图库里检索目标片段 → 标注迁移 → 坐标换算 → 生成 `_hdc.csv` / `_label.csv` → 直接喂 `HDCPointLevelDataset`。两个试点录制已跑通（样本池 1855 / 1645）。
3. **HDC 算法当前是坏的**：P=R=F1=0，根因已定位到四条（见 §2.4），不要在没有修复的情况下拿它做任何对比结论。

**三条红线**：

- **不要把 `D:\HDC\data\` 提交进 Git**（63 万张图 ≈ 12GB）。`.gitignore` 已加规则，新增数据目录也要加。
- **不要按窗口随机切分数据集**。步进图相邻重叠 888px，随机切分 = 标签泄漏 = 论文作废。必须**按录制（recording）分组切分**。
- **不要改标签口径 / channels 配置来"提升指标"**。label 0–19 的定义、`BeamAngle`、`BeamOffset`、channels 的 0-based/1-based 约定必须冻结；换配置会静默改变分母，历史指标不可比。

## 1. 项目背景

### 1.1 业务问题

钢轨在长期载荷下会产生核伤、螺孔裂纹、水平裂纹、轨底断裂等内部伤损。探伤仪用 9 个超声通道扫查，操作员看 B 显图像人工判伤。目标是把这个判断过程自动化：

- **输入**：B 显图像（1888×512，固定调色板渲染），或 9 通道 A 扫数据（encoding / 声程 / 深度 / 幅度）；
- **输出**：伤损的位置（图上的框 / 里程区间）与类别（核伤、螺孔裂纹……）；
- **约束**：现场设备算力低、标注数据少、要求结果可追溯（不能是黑箱）。

### 1.2 数据形态（必须记住的物理口径）

| 项 | 事实 | 来源 |
|---|---|---|
| B 显画布 | 1888×512，285.67 px/m，0 点 = 画布中心 x≈945 | `tools/find_pattern.py` 实测 |
| 通道俯仰角 | 通道 1–6 = 70°，7–8 = 37°，9 = 0°（1-based） | `docs/重新整理的HDC算法需求.md` L139-143 |
| 通道水平角 | 通道 1–4 = α（12~20° 可变），5–9 = 0° | 同上 |
| 拼孔值 | 10, 60, 20, 50, 30, 40, 0, 70, 80 | 同上 |
| 代码里的 channels | **0-based**：`channels=[8]` = 物理通道 9 = 俯仰 0° | `config.py` |
| 步进图 | `_Step-N.png`，名义步长 1000px，相邻重叠 888px；**方向分两种**（见 §8） | 实测 |
| 标签 | 0=正常；1–11=伤损；12–19=正常结构（接头/螺孔/导线孔/焊缝/鱼鳞/轨底锈蚀/焊筋/道岔） | `gui/type_selector.py` |
| 结构标签换算 | 结构子类 id 1–9 → 标签 12–20（实测：螺孔 id=2 → 13） | 实测 label CSV |

### 1.3 技术路线决策（2026-10-21 明确）

```
                    ┌─────────────────────────────────────────┐
B 显图像 / A 扫数据 → │  数据准备：检索 / 标注迁移 / 坐标换算      │
                    └───────────────┬─────────────────────────┘
                                    │ 同一份数据、同一套切分
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
        ┌───────────────────────┐       ┌───────────────────────┐
        │ 主线：图像识别          │       │ 对照：HDC 点级分类      │
        │ YOLO / CNN 检测+分类   │       │ 9 通道超维编码 + 原型    │
        └───────────┬───────────┘       └───────────┬───────────┘
                    └───────────────┬───────────────┘
                                    ▼
                        统一评估 + 论文（精度/数据效率/成本）
```

**为什么主线换成图像识别**：B 显图像本身已经是探伤仪对 9 通道数据的可视化，伤损在图上呈现为固定的空间纹理 + 色标；2025 年的公开工作（YOLOv8/v9 系列）在钢轨 B 显上已报 95%~99.5% AP，工程上可落地。HDC 作为对照，价值在"低资源、小样本、可增量、可解释"，不是拼峰值精度。

**为什么还保留 HDC**：论文的核心是对比；而且 HDC 若修好，能在无 GPU 的现场设备上跑，是图像模型的补充而非替代。

**标定的三个坑**（已在 `px2encoding.py` 里处理，改动前先读源码注释）：

1. 单步窗口内 mode M/P 等价 ⇒ 必须用"锚点图在相邻步的孪生命中"跨步判方向；

### 2.4 HDC 算法现状（重要：当前不可用）

`models/hdc_point_level.pth` 在，但 2026-02-14 的三次评估均为 **P=R=F1=0，Total Pred=0**。根因四层（完整证据见 `docs/算法原理图解与问题清单_20261012.md`）：

1. **`_create_encoder` 全项目无定义**（`test_hdc_unified.py:348/486` 调用）⇒ 9 通道 + 已有 `.pth` 时 `load()` 必崩 `AttributeError`。现在 pth 已落盘 ⇒ 下一次运行必崩（定时炸弹）。
2. **训练集只有 1 个文件**，正样本只在通道 8 上有 8 个点；通道 0–7 正样本 = 0。
3. **Centroid 零初始化 + `add_online` 的"is_wrong 全 False 则 return"** ⇒ 无正样本通道 argmax 恒为 0 ⇒ 永远"全对" ⇒ 永不更新 ⇒ 原型恒零（实测 2/180 个类原型非零）。
4. **判据 `md > ns + margin` 在原型范数失衡时恒假**：通道 8 真实读数 `normal_sim` 均值 0.9181，`max_defect` 峰值 0.1837 ⇒ 判据不可能成立。

> 🔴 一条必须继承的教训：**编码与原型必须同源**。早期诊断脚本只 load 了原型、没 load encoder，导致样本 HV 与原型 HV 近似正交，判据退化成"`md > 0`"，任何噪声都通过——得出的"通道 8 判据通过 1288"等结论全部作废。改任何编码参数，必须连原型一起重训。

其他已确认缺陷（修复时一并处理）：

- 首训用 OnlineHD，`load()` 却用 NeuralHD（结构碰巧兼容，语义不同）；
- 增量学习形同虚设：`learned_files` 含 train 唯一文件 ⇒ `actual_new_files` 恒空 ⇒ 永不训练；
- 指标把 train+test 混算，报告却写"训练集评估报告"；
- `process_prediction_results` 用**全局** predictions 填**单文件**矩阵 ⇒ 跨文件 encoding 重叠时串台；
- `Level(256, 8192)` 相邻级别相似度 0.9961 ⇒ 256 个 level 挤在一个 span，超出 8192 维的分辨力（经验 O(√D)≈90）。`randomness` 不是可用旋钮（r 0→0.8 只降到 0.9808，r=1.0 悬崖崩到 0.0003）。

## 3. 待办任务与优先级

> 优先级定义：**P0 = 不做就没有可交付的识别系统/论文数据；P1 = 决定论文能否成立；P2 = 工程化与写作。**
> 每项都给"产出 / 验收 / 依赖"，不要用"跑通了"当验收。

### P0-1 数据契约与数据集冻结

- **做什么**：把 311 张查询、263 张命中、118 个录制整理成一份**不可变**的 manifest；每条记录带 `sha1`、录制键、类别（从文件名弱标签 + 人工确认）、命中位置、数据可用性（有无 JSON/标注）；按录制划分 train/val/test（建议 70/15/15，且 test 至少留 20 个录制）。
- **产出**：`output/dataset_v1/manifest.csv` + `split.json` + `README.md`（含生成脚本）。
- **验收**：同一录制不出现在两个 split；manifest 行数 = 311；每条命中能在磁盘上找到文件；sha1 可复算。
- **依赖**：无。**这是所有训练的前置，先做。**

### P0-2 图像识别基线（主线）

- **做什么**：B 显图像 → 伤损检测/分类。两条路先各跑一个最小基线：
  - **A. 切片分类**：以命中位置为中心取 512×512（或 1024×512）切片，训 ResNet18/EfficientNet-B0 做多类分类；
  - **B. 目标检测**：YOLOv8n/YOLOv9n，输入 1888×512（可切 640 重叠块），预测伤损框 + 类别。
- **标签从哪来**：① 文件名里的类别词（核伤/螺孔裂纹/焊缝/鱼鳞/轨底锈蚀…）做图像级弱标签；② B 显图上的彩色标记做框提议；③ 用 `check_viewer.py` 人工确认。**三者必须交叉验证，不能只用颜色**（否则模型学的是调色板，不是伤损纹理）。
- **产出**：训练脚本 + 权重 + 评估报告（per-class P/R/F1、AP@0.5、混淆矩阵）+ 20 张可视化。
- **验收**：在**留出录制**上报告指标；给出"去色/灰度"消融，证明模型不是只靠颜色；训练/推理耗时、模型大小写进报告。
- **依赖**：P0-1。

### P0-3 标注 → 检测框转换器

- **做什么**：把设备侧标注 JSON（点级：`e / channel / depth / amplitude`）转成像素坐标与检测框，供检测模型用；同时支持反向（框 → E 区间 → CSV 行）。
- **产出**：`tools/annotation_to_boxes.py`（新），输入 `*.xxc标注.json` + `标定表.json`，输出 YOLO txt / COCO json / 可视化。
- **验收**：在 200922_17387 上，171 个标注点全部落在框内；抽 20 个框肉眼核对；与 `px2encoding.py` 的 E 换算结果一致（误差 ≤2px）。
- **依赖**：P0-1；标定表。

### P0-4 统一评估协议

- **做什么**：写死一份评估脚本，HDC 与图像模型共用：同一 test 集、同一标签映射、同一指标函数；输出 CSV + 图表。
- **指标**：per-class P/R/F1、macro-F1、AP@0.5、混淆矩阵；另报数据效率曲线（n=10/50/100/500/2000）、训练时长、推理延迟、模型大小、增量更新耗时。
- **验收**：任何模型只需实现 `predict(manifest_row) -> [(label, score, box)]` 就能接入；报告可由一条命令重跑。
- **依赖**：P0-1。

### P1-1 HDC 链路修复

- **做什么**：按 §2.4 四条根因逐条修：
  1. 实现 `_create_encoder`（或删掉 9 通道 load 分支），保证 save/load 同构；
  2. 训练集补齐：至少让通道 0–7 有正样本，或明确只训有正样本的通道；
  3. 原型初始化改为"首样本即原型"或 balanced centroid，禁止零初始化 + 空更新；
  4. 判据改为**归一化相似度 + 每类阈值**（或 z-score），不再用裸 cosine margin。
- **产出**：修复后的 `hdc_point_level_classifier.py` + 单测 + 一份"修复前后对照"报告。
- **验收**：单文件 180123 上 Total Pred > 0；P/R/F1 与混淆矩阵可复现；`test_hdc_unified.py` 全过。
- **依赖**：P0-1（数据）。

### P1-2 HDC 编码重设计

- **做什么**：当前是"原始声程值 → Level 编码 → 128 位置 bundle"，判别信息被公共分量淹没。按文献（EWSHM 2026 的 SHM-HDC）改成**特征工程 + 联合编码**：
  - 每通道提取：包络峰值、TOF、峰值幅度、AR 系数、短时能量/时频描述子；
  - 编码：`bind(Random(通道), Random(特征类型), Level(量化值))` → bundle → normalize；
  - 先做**去均值/白化**（每个通道减训练集均值），再 bundle；原型单位化；
  - 降 `NUM_LEVELS` 或提 D，二选一，做消融。
- **产出**：`hdc_features.py` + 编码消融报告（不同特征/level/D/归一化）。
- **验收**：在 pilot 样本池上，缺陷类的 `md - ns` 分布与正常类**可分离**（AUC > 0.8 为及格）；给出编码前后相似度分布图。
- **依赖**：P1-1。

### P1-3 对照实验（论文核心）

- **做什么**：同一数据、同一 split、同一指标，跑三组：
  - 赛道 A：同数据不同表征——HDC vs 1D-CNN（都吃 9 通道序列）；
  - 赛道 B：同任务不同模态——HDC（信号）vs 2D-CNN/YOLO（B 显图）；
  - 数据效率：每类 n=10/50/100/500/2000，画学习曲线。
- **产出**：`output/compare_v1/`（结果 CSV + 图 + 结论草稿）。
- **验收**：每个数字都能追溯到脚本与随机种子；至少 3 个种子取均值±标准差；test 集只用于最终报告。
- **依赖**：P0-4、P1-2、P0-2。

### P1-4 视频/序列一致性（若"视频识别"指 B 显回放序列）

- **做什么**：单帧检测 → 多帧投票/跟踪（IoU 匹配 + 轨迹确认），压掉单帧虚警；输出"伤损事件"而非"单帧框"。
- **产出**：`tools/temporal_fusion.py` + 前后对比（虚警率/漏检率）。
- **验收**：同一段回放，虚警率下降 ≥30% 且漏检不升；延迟满足在线（≥10 FPS）。
- **依赖**：P0-2。**若"视频识别"另有所指（如摄像头视频），先找老大确认数据源，不要自行假设。**

### P2-1 工具工程化

- 把 P0-3、P1-2 接入现有 GUI/单文件分发；保持"双击即用"；加断点续跑、日志、失败隔离。
- **验收**：同事机器上无 Python 环境也能按 README 跑通；单文件 < 200KB；关窗零残留。

### P2-2 论文写作

- 结构建议：问题 → 数据与标注 → 方法（图像主线 + HDC 对照）→ 实验协议 → 结果（精度/数据效率/成本）→ 讨论（互补而非替代）→ 局限。


- `是否命中` ∈ {是, 疑似, 否}；`层级` ∈ {T1,T2,T3,T4,-}；
- `位移(px)` 是查询图左缘在命中 Step 图中的列号；`区间(px)` = `[位移, 位移+查询宽)`；
- `NCC` 可为空（越界/无法计算），空值不等于 0。

**② 标注 JSON `*.xxc标注.json`**

```json
{
  "annotations": [
    {
      "id": "...",
      "type": "damage|structure",
      "subtype": {"id": "11", "name": "螺孔裂纹"},
      "points": [{"e": 1008, "channel": 6, "depth": 92.0, "amplitude": 100.0}],
      "start_E": 1008, "end_E": 1013,
      "channels": [6, 7, 8],
      "timestamp": "..."
    }
  ],
  "timestamp": "...", "version": "..."
}
```

- `e` 是**原始 E（未减 BeamOffset）**；`channel` 是 1-based 物理通道；
- `subtype.id`：伤损 1–12，结构 1–9（结构落 CSV 时 +11）。

**③ 样本 CSV 三件套**

```
*_hdc.csv      : encoding, channel_0..channel_8        # 声程值
*_label.csv    : encoding, label_0..label_8            # 0/1..20
*_encoding.csv : encoding 及换算中间量（可选）
```

- 行按 `encoding` 升序；`encoding = original_e − BeamOffset[channel]`；
- 逆算：`original_e = encoding + BeamOffset[channel]`。

**④ 标定表 `标定表.json`**

```json
{"<录制>": {"mode": "M|P", "D": -464374, "residual_px": 1.5, "n_match": 5,
            "anchor": {"query": "...", "step": 465000, "shift": 1374.0},
            "fragment_json": "...", "image_dir": "..."}}
```

**⑤ 数据集 manifest（P0-1 新建）**

```
sample_id, query_file, sha1, recording, batch, label_name, label_id,
hit_file, hit_folder, shift_px, x0, x1, ncc, cov, split, has_json, has_annotation
```

## 6. Token 高效协作规范

目标：**用最少的上下文换最大的确定性**。以下规则对双方都适用。

### 6.1 提问模板（每次一条，复制即用）

```
【目标】一句话说清要什么结果
【输入】绝对路径（文件/目录）+ 关键字段
【约束】不能做什么（如：不要跑全量、不要改 data/）
【验收】什么算完成（指标/文件/命令输出）
【已有证据】已排除什么、上次结论是什么（引用 docs 路径）
```

反例：`"帮我看看这个项目"`、`"为什么效果不好"`、贴 200 行日志。
正例：`"用 output/dataset_prep/pilot_200922_17387 跑 HDC 基线，只跑通道 8，要 P/R/F1 和混淆矩阵；不要改 config.py；完成标准是 test_hdc_unified.py 能复现同一数字。"`

### 6.2 让 agent 自己取上下文

- 给**路径**，不要粘贴文件内容；agent 有 Read/Grep/Glob。
- 给**行号或函数名**，不要整段贴代码。
- 让 agent 先跑 `grep -n` / `sed -n` 定位，再改；不要让它"猜文件"。

### 6.3 输出要摘要，不要 dump

- 长任务让脚本把结果写 CSV/JSON，回复里只贴**前 10 行 + 统计**；
- 日志写文件，用 `tail -20` 或 `grep "== 完成"` 取关键行；
- 图片只给**路径**，让 agent 用 Read 看；不要 base64。

### 6.4 批量与增量

- 一次问完一组相关问题（不要 10 轮问 10 个参数）；
- 改代码用**最小 diff**，不要重写整文件；
- 先 5–10 个样本试跑，再全量；试跑结果给"是否继续"的判据。

### 6.5 明确的"停止条件"

每个任务开头写清：**什么情况下停下来问**（例如"如果 test 集指标比 val 低 10 个点以上，停下报告，不要调参"）。避免 agent 无限试错烧 token。

### 6.6 会话交接

- 每次会话结束前，让 agent 更新 `D:\HDC\.workbuddy\memory\YYYY-MM-DD.md`（追加：做了什么、证据、下一步）；
- 长期结论写 `MEMORY.md`；细节写 `docs/`，不要都塞进记忆。
- 新会话开场只需一句："读 `.workbuddy/memory/MEMORY.md` 和今天的日志，然后做 X。"

### 6.7 看图规则

- 需要判断"这张图对不对"时，给**具体文件路径**，不要文字描述"左边有个紫条"；
- 一次最多 3–4 张，多了让 agent 先做拼图/缩略图；

## 8. 红线与已知坑

1. **数据泄漏**：步进图相邻重叠 888px；随机按窗口切分 = 同一位置同时进 train/test。必须按录制分组。
2. **dmap 带屏蔽必须与标记框保护配对**：`dmap(a, protect=marks)`。y350–412 屏蔽红基线/红字时，会把轨底伤损标记整条误杀；全零模板还会让 `matchTemplate` 输出常量 1.0，伪装"完美匹配"。
3. **调色板必须含 cyan (0,192,240)**；纯红 (240,0,0) 与基线同色，当前无法提取（少量查询受限）。
4. **步进方向分两种**：0646 系 `K=x+N`，第三批多为 `K=x−N`；换算前必须用锚点实测 mode + D，**不可套用其它录制的常数**。
5. **单标记查询有"泛型噪声底"**：同组多文件 0.7~0.86 扎堆、top1≈top2；dmap 残差近乎色盲（绿标/紫标同分）。兜底全扫必须"单峰突出 top1−top2≥0.15 + 颜色校验"。
6. **ProcessPoolExecutor 脚本必须 `if __name__ == "__main__"`**（Windows spawn 会重跑主模块，递归起进程）。
7. **同文件多处 Edit 必须串行**，改完 `grep` + `ast.parse` 复核；本机实测并行 Edit 会静默丢改动。
8. **不要用 `timeout` 包装 GUI 测试**；不要用 `| tail` 观察 GUI 输出（吞输出）；结果写文件再读。
9. **`config.json` 不存在** ⇒ 走默认：threshold=0 / margin=0 / channels=[0..8] / epochs=1 / onlinehd。改默认值等于改实验语义。
10. **指标分母会变**：`Total True=93` 只统计 `label_8`；9 通道全统计是 191。任何跨配置比较先对齐分母。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| B 显 | B-scan，横轴里程/位置、纵轴深度的超声图像 |
| A 扫 | 单通道回波幅度-时间序列 |
| encoding | 编码值 = 原始 E − BeamOffset[channel] |
| E | 探伤仪的编码器位置（原始里程计数） |
| 通道 | 9 个超声探头/角度组合；1-based 与 0-based 混用，务必看清 |
| 拼孔值 | 各通道的探头组合参数（10,60,20,50,30,40,0,70,80） |
| Step-N | 步进图文件名中的 N，表示该图左缘对应的位置 |
| 孪生命中 | 同一物理位置出现在相邻两张 Step 图中的现象 |
| dmap | 残差图：墨迹强度 × 饱和度权重，屏蔽结构/文字行 |
| NCC | 归一化互相关，像素级复核分数 |
| 弱标签 | 从文件名、色标、检索结果自动推导的标签，需人工抽验 |
| HDC | Hyperdimensional Computing，超维计算/向量符号架构 |
| 原型 | 每类样本 HV 的聚合向量，分类时取最大相似度 |
