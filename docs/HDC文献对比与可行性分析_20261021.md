## 0. 结论摘要（先看这 6 条）

1. **HDC 不是"另一种更准的模型"，它是"随机特征 + 原型/线性分类器"的一种高效实现。** 理论上等价于核方法（Dewulf 等 2023）：`φ(x)` 是随机特征映射，原型是类条件均值，分类是内积。**编码不变，换分类器救不了**。
2. **文献支持 HDC 的"低资源、小样本、快训练、抗噪、可增量"，但不等价于"精度超过 CNN"。** 2025 年大规模复现（121 个 UCI 数据集）明确结论：HDC 方法进步明显，但**常被现成 ML 方法超过**；优势在效率与 few-shot 泛化。
3. **与本项目结构最像的工作是 EWSHM 2026 的 SHM-HDC**（`10.58286/33696`）：重叠窗口 + 时频/AR 特征 + "通道位置/特征类型/量化值"联合编码 + 原型分类 → **95.08%、250KB、毫秒级**。它**没有**直接用原始幅值 + 256 级 Level —— 这正是本项目当前最大的方法差距。
4. **本项目 HDC 现在 P=R=F1=0，不是"HDC 不行"，是四层工程/表示缺陷叠加**：`_create_encoder` 缺失、训练集无正样本、原型零初始化死锁、判据在原型失衡时恒假（详见 §5）。**在这些修好之前，任何"HDC 不如视觉"的结论都不成立。**
5. **图像识别作为对照是可行的，但不是主线**：钢轨 B 显的公开工作已报 92.3%~99.5% AP（YOLOv3/v8/v9 系列），足以作为论文的视觉基线；但它依赖大量框标注、算力更高、模型更大，不符合“现场低资源”的产品目标。主要风险是**标签质量、类别稀缺、按录制切分、渲染伪影**。
6. **论文的立论应是"互补而非替代"**：HDC 打"数据效率 / 无 GPU / 在线增量 / 可解释 / 模型体积"，视觉打"峰值精度"。用同一数据、同一 split、同一指标，报学习曲线与成本，而不是拿 HDC 的 95%（SHM 数据集）去对 YOLO 的 99.5%（B 显数据集）。

## 4. 理论分析

### 4.1 HDC 的数学身份：随机特征 + 类均值

设编码 `φ(x) ∈ R^D`，类原型 `c_k = (1/n_k) Σ_{i∈k} φ(x_i)`，判别 `ŷ = argmax_k ⟨φ(x), c_k⟩`。

这正是**核分类器**：核 `K(x,y) = ⟨φ(x), φ(y)⟩`，原型是类条件核均值。Dewulf 等（L3）证明 HDC 变换可写成核均值嵌入；随机特征在 D 足够大时逼近通用核。由此得到三条硬结论：

1. **HDC 的表达能力由 `φ` 决定，不由"超维"决定。** 如果 `φ` 把不同类映射到几乎相同的方向，任何原型/阈值/增量策略都救不了。
2. **原型分类器是线性分类器（在 φ 空间）。** 类边界是超平面；对非线性可分的任务，需要 `φ` 提供足够好的特征，或加核/多层。
3. **"超维"带来的是近正交性与抗噪，不是精度。** 近正交让不同符号易区分；但同类样本的公共分量也会被放大（见 4.3）。

### 4.2 容量与分辨率：256 级 Level 在 8192 维里放不下

- 随机向量余弦的标准差 `σ ≈ 1/√D`。D=8192 ⇒ σ≈0.011。**小于 0.01 的相似度差异在统计上没有意义。**
- 捆绑 n 个等权单位向量，对任一分量的相似度约 `1/√n`。128 个位置 ⇒ ≈0.088；若再把 9 通道混在一起，≈0.029。**窗口内位置越多，单个位置的信号越被稀释。**
- Level 编码把 L 个量化级插值在两条基向量之间；相邻级的余弦由插值步长决定。本项目实测 **L=256 时相邻余弦 0.9961**（`docs/randomness扫描实验报告_20261012.md`）。要让相邻级可区分，级间差异必须大于噪声底 ~1/√D；一维插值能提供的可分辨级数约 **O(√D)≈90**。
- 结论：**256 级 > 90 级的分辨力 ⇒ 量化级混叠**。相邻的声程值被编成几乎相同的 HV，编码器在"幅值轴"上实际只有 ~90 个有效刻度。项目里"相邻相似度 0.9961"不是 bug，是**维度与级数不匹配**；`randomness` 也不是旋钮（r 0→0.8 只降到 0.9808，r=1.0 悬崖崩到 0.0003）。

**可行修改**（任一，需消融）：
- 降 `NUM_LEVELS` 到 32/64/90；
- 提 D 到 16384/32768；
- 换去随机化码本（L9）；
- 改用**多级/多维度编码**（如每维独立量化 + 随机投影），而不是单 span 插值。

### 4.3 公共分量：为什么 `normal_sim` 会到 0.918

把窗口写成：

```
B = Σ_i level(v_i) ⊗ pos_i
```

`pos_i` 对所有样本相同；`level(v_i)` 因为相邻级高度相似（0.9961），彼此差异很小。于是：

```
B ≈ (Σ_i pos_i) ⊗ level(v̄)  +  Σ_i (level(v_i) − level(v̄)) ⊗ pos_i
        └──── 公共分量（占主导）────┘      └──── 判别分量（很小）────┘
```

- 公共分量对所有样本几乎一样 ⇒ 任意两个样本的余弦都接近 1；
- 判别分量的能量占比 ≈ `Var(v) / (Mean(v)² + Var(v))`，对含大量零/直流偏置的超声信号很小；
- 结果：`normal_sim` 高（0.918）不是"模型学到了正常"，而是**编码饱和**；`max_defect` 低（0.184）也不是"缺陷可分"，而是**缺陷原型几乎为零**（§4.4）。

**修法**：先做**去均值/白化**再 bundle。最简单有效的是每个通道减训练集均值（或每个窗口减自身中位数），再 normalize；更强的是用残差编码（`v_i − median(window)`）或对原始窗口做随机投影。**没有这一步，增加数据/换分类器都不会改变"所有样本都像"的事实。**

### 4.4 原型死锁：为什么 `Total Pred=0`

本项目的训练循环：

```
Centroid 零初始化
  → argmax 恒为 0（所有原型为零，相似度全 0）
  → 与标签比：若标签也是 0，则"全对"，is_wrong 全 False
  → add_online 直接 return，不更新
  → 原型永远为零
```

这是一个**自锁**：没有正样本的通道（0–7）永远学不到东西；有正样本的通道（8）也因为"零原型 + argmax=0"先锁死。实测 2/180 个类原型非零，与此完全一致。

**修法**（按优先级）：
1. **首样本即原型**（或每类取第一个样本的 HV），打破零初始化；
2. **有监督类均值**：`c_k = mean(φ(x_i) for y_i=k)`，不要依赖在线误分类更新；
3. **balanced centroid**：每类等权采样，避免先验偏置；
4. 若保留 OnlineHD，至少加"每类至少更新一次"的保底规则 + 学习率衰减。

### 4.5 判据：`md > ns + margin` 为什么恒假

- 该判据假设"缺陷原型比正常原型更近"，且两者的相似度尺度可比。
- 在原型范数/训练量不均衡时：正常类样本多 ⇒ 原型均值稳定、`ns` 高；缺陷类样本少 ⇒ 原型噪声大、`md` 低。**这不是阈值没调好，是两类原型质量不对称。**
- 正确做法：
  - 原型**单位化**后比较；
  - 用**每类 z-score**：`z_k = (sim_k − μ_k) / σ_k`，在验证集上估计 `μ_k, σ_k`；
  - 或用**ROC/PR 曲线**选阈值，按目标召回/虚警率定；
  - 多类时用 `argmax` + 拒识（open-set），不要用"正常 vs 缺陷"的单一 margin。

### 4.6 数据效率的真实边界

- 原型估计误差 ~ `σ/√n`。n=10 时，正交方向上的噪声约 0.32；n=100 时约 0.1。**如果类间差异只有 0.01~0.05（本项目当前就是这个量级），few-shot 不可能成立。**
- HDC 的 few-shot 优势成立的前提是：**编码已经把类间差异放大到 >> 1/√n**。L8 用特征工程做到这一点；本项目没有。
- 因此：**先修表征，再谈小样本**。在表征修好之前做"n=10 vs n=100"的学习曲线，只会得到"两者都接近 0"的平坦线。

### 4.7 鲁棒性与可解释性

- **鲁棒性**：分布式表示对位翻转/传感器漂移有 graceful degradation（L1：40% 位翻转内性能稳定）。这对超声探伤的耦合剂变化、探头磨损是实打实的优势，可作为论文的一个卖点。
- **可解释性**：原型相似度只能说明"像哪类"，不能说明"哪个通道/哪段深度导致的"。若论文要打"可解释"，需要额外做**通道/位置遮挡归因**（occlusion sensitivity on HV components）或**原型最近邻样例**，不要空口说"HDC 天生可解释"。

## 6. 可行性判断（分任务）

### 6.1 作为"图像对照基线"（不是主线）

**可行，但只用于论文对照，不作为产品交付模型。**

- 数据：311 查询、263 命中、118 录制；B 显图 1888×512，公开工作已证明 YOLO 系列可做。
- 标注：当前只有 2 类点级标注（螺孔/螺孔裂纹），**类别严重不足**；必须用文件名弱标签 + 色标提议 + 人工确认扩充。
- 主要风险：
  1. **标签泄漏**（步进重叠）→ 按录制切分；
  2. **渲染伪影**（固定调色板/网格/文字）→ 灰度/去色消融，证明模型学的是回波纹理；
  3. **类别不平衡**（缺陷远少于正常结构）→ 重采样/焦点损失/按类报指标；
  4. **域偏移**（不同探伤仪/线路/年份）→ 留出录制测试，报告跨录制泛化。
- 预期：在自建 test 上达到"可用"（macro-F1 > 0.7）是合理目标；不要承诺 99%，公开数字不可直接搬。它的作用是回答"同一批数据，HDC 与视觉差多少"，不是替代 HDC。

### 6.2 作为"主力识别方案"（HDC）

**2026-10-21 已修复链路：pilot 留出录制 F1=0.542、AUC 0.92~0.99；长期上限取决于数据与特征工程。**

- 可行条件：
  1. 编码去公共分量（去均值/白化）；
  2. Level 数与 D 匹配（32–90 级，或 D≥16384）；
  3. 每通道独立归一化 + 通道特定窗口/特征；
  4. 原型有监督初始化 + 单位化 + 每类阈值；
  5. 按录制切分，报 per-class 指标。
- 合理的预期：在"小样本、无 GPU、需在线增量"的场景下，HDC 能接近轻量 CNN 的 F1，同时训练/推理成本低一个量级以上。**不要预期它在峰值精度上超过 YOLO。**
- 论文价值：不是"HDC 更准"，而是"在标注稀缺的现场条件下，HDC 的性价比更高；视觉负责高精度离线复核，HDC 负责在线初筛"。

### 6.3 作为论文

**可行，但必须换赛道。**

- 如果论文主张"HDC 优于视觉"：**不成立**，文献与数据都不支持（视觉 B 显已 92–99.5% AP）。
- 如果论文主张"HDC 与视觉互补，且在低资源/小样本/增量场景更优"：**成立**，且有 L4/L5/L6/L8 的支撑。
- 建议的实验矩阵：
  - 精度：per-class F1 / macro-F1 / AP@0.5；
  - 数据效率：n=10/50/100/500/2000 的学习曲线；
  - 成本：训练时长、推理延迟、模型体积、能耗（可用 GPU 功耗估算）；
  - 增量：新增录制后增量更新 vs 全量重训的精度/时间；
  - 鲁棒性：加噪声/通道缺失/幅值漂移下的性能下降；
  - 可解释：原型最近邻 + 通道遮挡归因。
- 预期结论：**HDC 在 n 小、无 GPU、需增量时占优；视觉在数据充足、离线复核时占优。**
- 论文风险：审稿人会问"为什么不直接用 YOLO"——必须用上面的成本/数据效率曲线正面回答，而不是回避。

## 7. 修复与实验建议（映射到交接文档的任务）

| 实验 | 目的 | 变量 | 成功判据 | 对应任务 |
|---|---|---|---|---|
| E1 编码消融 | 找可分的表征 | 原始 vs 去均值 vs 白化 vs 残差；L=32/64/90/256；D=4096/8192/16384 | 缺陷 vs 正常 AUC > 0.8 | P1-2 |
| E2 原型构造 | 打破死锁 | 零初始化 vs 首样本 vs 有监督均值 vs balanced vs OnlineHD | 非零原型 ≥ 90%；Total Pred > 0 | P1-1 |
| E3 阈值 | 稳定判据 | 全局 margin vs 每类 z-score vs ROC 校准 | 在验证集上虚警/漏检可控 | P1-1 |
| E4 特征工程 | 对标 L8 | 原始幅值 vs 包络/TOF/峰值/AR/时频 | macro-F1 提升 ≥ 10 个点 | P1-2 |
| E5 分组切分 | 防泄漏 | 随机窗口 vs 按录制 | 按录制指标下降可解释、无泄漏 | P0-1 |
| E6 视觉消融 | 防"学颜色" | 彩色 vs 灰度 vs 颜色随机化 | 灰度下性能下降 ≤ 10 个点 | P0-2 |

**执行顺序**：E5（切分）→ E2（原型）→ E1（编码）→ E4（特征）→ E3（阈值）→ E6（视觉消融）。**不要在 E5 之前报任何指标。**

## 8. 视觉基线的文献对照与风险

### 8.1 文献给我们的三个信号

1. **B 显 + YOLO 是成熟路线**：V1–V5 覆盖 YOLOv3/v8/v9，精度 92.3–99.5%，且有轻量化（参数 −91%~−94%）版本，适合现场部署。
2. **小目标/密集目标是难点**：V2 用 RepHGNetv2 + 注意力提召回；V4 去掉 P5 检测头、加 P3–P4，专攻小目标。我们的伤损（核伤、螺孔裂纹）在 1888×512 上也是小目标，应优先保留高分辨率特征层。
3. **数据增强是刚需**：V3/V4 都强调 B 显专用增强。我们只有 263 张命中，必须用强增强 + 预训练 + 迁移。

### 8.2 我们不能直接搬数字的原因

- 公开数据集的类别、标注粒度、测试集划分与我们不同；
- 他们多是"整图 → 框"，我们是"检索片段 → 点级标签"，标签噪声更大；
- 他们的 B 显渲染参数（增益/抑制/标尺）可能与我们的设备不同 ⇒ 域偏移。

### 8.3 必须做的三个防守实验

1. **去色消融**：灰度输入 vs 彩色输入。若灰度掉点 > 20%，说明模型主要靠色标，不是回波纹理。
2. **跨录制测试**：train/val/test 按录制分组；另留 5 个"完全没见过的年份/机号"做 external test。
3. **标注噪声评估**：抽 50 个框人工复核，报"弱标签 vs 人工标签"的一致率；若 < 85%，先修标签再训模型。
