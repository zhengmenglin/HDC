## 2. 修了哪些 bug（按根因，不按表象）

### B1 `_create_encoder` 缺失 → 9 通道 load 必崩

- **症状**：`AttributeError: 'HDCUnifiedModel' object has no attribute '_create_encoder'`
- **根因**：`test_hdc_unified.py:348/486` 调用，但方法从未定义；旧版能跑只是因为当时 `.pth` 不存在、走从零训练分支。
- **修复**：在 `HDCPointLevelModel` 增加 `_create_encoder(sample_shape)`，按窗口长度/通道数/Level 数创建编码器。
- **验证**：`hasattr(...,'_create_encoder') == True`；9 通道 load 成功。

### B2 原型零初始化 + `add_online` 空更新 → 永久死锁

- **症状**：`Total Pred=0`；实测 180 个类原型只有 2 个非零。
- **根因**：
  ```
  Centroid 零初始化 → argmax 恒 0 → 若标签也是 0，则 is_wrong 全 False
  → add_online 直接 return → 原型永远为零
  ```
- **修复**：改为**有监督类均值累加** `fit_centroids()`：
  `weight[class] += Σ hv`，`class_counts[class] += n`；cosine 对尺度不变，增量可直接累加。
  同时加 `defect_mask()`：训练集没见过的伤损类不参与判伤，避免零原型制造虚警。
- **验证**：类原型非零数 15/180（9 通道下 ch6/7/8 的 0/11/13 类）；预测非零。

### B3 判据 `md > ns + margin` 在原型失衡时恒假

- **症状**：`normal_sim≈0.918`、`max_defect≈0.184`，任何 margin 都过不了。
- **根因**：两类原型质量不对称（正常类样本多、伤损类样本少），裸 cosine margin 没有可比尺度。
- **修复**：训练集标定每通道 `(md−ns)` 的 `mu/sigma`，推理用
  `z = (md − ns − mu) / sigma > z_threshold`（默认 2.75）。
  标定退化（sigma<1e-4）时退回 `(0,1)`，避免把噪声放大成海量虚警。
- **验证**：z 扫描（9 通道）F1 峰值 0.5415 @ z=2.75；z=2.5 时 R=0.615、P=0.349。

### B4 Level 256 级挤在 8192 维里 → 量化混叠 + 编码饱和

- **症状**：相邻 Level 余弦 0.9961；所有窗口 HV 几乎同向。
- **根因**：单 span 塞 256 级，超出 8192 维经验分辨力（O(√D)≈90）；且原始幅值有强公共分量（ch8 底波 mean≈134）。
- **修复**：
  1. `NUM_LEVELS` 默认 **64**；
  2. `input_mode="window_z"`：每个窗口/通道先减均值除标准差，再映射到 Level；
  3. `raw` 模式保留，供消融。
- **验证**：`normal_sim` 从 0.918 降到 0.885，`defect` 均值转正（+0.04~+0.05），AUC 0.92+。

### B5 9 个通道共用"混合 HV" → 通道互相稀释

- **症状**：3 通道 F1 0.58，改成 9 通道 F1 掉到 0.24。
- **根因**：旧编码把所有通道 `sum` 成一个 HV，9 个分类器共用；通道越多，单通道信号越被稀释。违反"9 通道独立建模"的设计。
- **修复**：`forward(per_channel=True)` 返回 `[B,C,D]`，每个通道用自己的 HV；分类器/岭回归/预测都按通道取 `hv[:, i]`。
- **验证**：9 通道 F1 从 0.24 回到 0.44（z=2.5）/0.54（z=2.75），与 3 通道同量级。

### B6 CUDA OOM：整窗一次物化 `[B,128,C,8192]`

- **症状**：`CUDA out of memory. Tried to allocate 4.50 GiB`（batch=128）。
- **根因**：单张量 128×128×9×8192×4B ≈ 4.5GB，bind 还会复制一份。
- **修复**：编码器按位置分块（`chunk_size=8`），每块只物化 `[B,8,C,D]`，峰值降到 ~1/16。
- **验证**：batch=128、9 通道、D=8192 全流程通过。

### B7 训练文件被重复计入（1855 → 3710）

- **症状**：`all: 200922... 使用所有 1855 个样本` 打印两次，数据集 3710。
- **根因**：`get_json_files()` 同时 glob `*.json` 与 `*.xxc.json`，`*.json` 也匹配 `.xxc.json`，同一文件返回两次。
- **修复**：按 `resolve()` 绝对路径去重。
- **验证**：返回 1 个文件；训练样本 1855。

### B8 跨文件串台：全局 predictions 填单文件矩阵

- **症状**：不同文件 encoding 重叠时，A 文件的预测被写进 B 文件。
- **根因**：`process_prediction_results()` 遍历**全局** predictions，只按 `center_encoding` 查表，不校验 `info['file']`。
- **修复**：增加 `file_name` 参数，按文件名过滤。
- **验证**：`data/test` 多文件（含 3 份副本 + 180123 + 210514）逐文件指标正常，无串台。

### B9 指标混算 train+test，报告写"训练集"

- **症状**：一个总指标把训练集和测试集拼在一起，分母不可追溯。
- **根因**：`tasks = [(TRAIN, True, ...), (TEST, True, ...)]`，最后 `vstack` 一起算。
- **修复**：按 split 分开累计；测试集单独出报告（`hdc_test_report_*.txt`），训练集只作参考。
- **验证**：pilot 训练集 F1 0.846、测试集 F1 0.542，分别独立。

### B10 旧检查点"能加载但语义错"

- **症状**：v1 模型（raw 输入/256 级/零原型）与当前编码不兼容，静默加载会得到全错结果。
- **修复**：`load()` 检查 `version`；v1 直接抛明确错误，`run_unified_test` 捕获后自动 `--force-retrain`。
- **验证**：加载 `models/hdc_point_level.pth` → `ValueError: 旧版检查点...`；加载新模型往返指标完全一致（0.541516...）。

### B11 设备不一致：`class_counts` 被 `map_location=cuda` 搬到 GPU

- **症状**：增量训练 `RuntimeError: Expected all tensors to be on the same device`。
- **修复**：`class_counts` 固定 CPU；`load()` 后 `.cpu()`；`bincount` 结果只转 dtype。
- **验证**：CUDA 下 `fit_centroids(reset=False)` 通过，counts 正确累加。

### B12 ridge 路径在 8192 维用 `pinv` → 卡死

- **症状**：选择 `method="ridge"` 后长时间无输出（>10 分钟）。
- **根因**：`torchhd.functional.ridge_regression` 对 8192×8192 做 `pinv`。
- **修复**：改为对偶形式（n≪d 时解 n×n 系统）：
  `W = Xᵀ (X Xᵀ + αI)⁻¹ Y`；并同步 `class_counts`。
- **验证**：232 样本 1.3s 完成。**注意**：当前数据量下 ridge 仍退化（sigma≈0），默认不推荐；生产用 `centroid`。

### B13 日志污染：编码器每个 batch 打印相似度

- **修复**：删除 `forward` 里的 print；调试信息由 `HDC_VERBOSE=1` 控制。

### B14 单通道/多通道两套算法

- **症状**：单通道走 `OnlineHD(Sinusoid)`，多通道走 `Level`，指标不可比；`load()` 还固定用 NeuralHD。
- **修复**：统一走 `HDCPointLevelModel` 的 Level 编码 + 类均值；删除 141 行死代码。
- **验证**：`--channels 8` 单通道全流程通过（P=0.556/R=0.176/F1=0.268，数据受限）。

## 3. 主数据目录的结果（说明瓶颈在数据，不在代码）

`data/train`（仅 170921，8 个伤损点）→ `data/test`：

- 训练集：P=0.500 / R=0.625 / F1=0.556（8 个真值）
- 测试集：P=0.600 / R=0.082 / F1=0.144（183 个真值）

**为什么低**：训练集只有 170921 一个文件、伤损点只在 ch8 有 8 个；测试集 180123 的 159 个真值主要在 ch6/7，训练时这两个通道**零正样本** → `defect_mask` 直接不判。这不是回归，是数据缺口。

## 4. 复现命令

```bash
# 1) 两个 pilot 录制（推荐：能体现真实能力）
D:/HDC/.venv/Scripts/python.exe test_hdc_unified.py \
  --train-dir D:/HDC/output/dataset_prep/pilot_200922_17387 \
  --test-dir  D:/HDC/output/dataset_prep/pilot_210201_18277 \
  --model D:/HDC/output/hdc_fix_20261021/hdc_point_level.pth \
  --results-dir D:/HDC/output/hdc_fix_20261021/results \
  --channels 0,1,2,3,4,5,6,7,8 --force-retrain --z-threshold 2.75 --no-plots

# 2) 主数据目录（会暴露数据缺口）
D:/HDC/.venv/Scripts/python.exe test_hdc_unified.py \
  --train-dir D:/HDC/data/train --test-dir D:/HDC/data/test \
  --model D:/HDC/output/hdc_fix_20261021/hdc_canonical.pth \
  --results-dir D:/HDC/output/hdc_fix_20261021/canonical \
  --channels 0,1,2,3,4,5,6,7,8 --force-retrain --z-threshold 2.75 --no-plots

# 3) 单通道
... --channels 8 ...
```

**注意**：
- 换编码/修 bug 后必须 `--force-retrain`；否则会拒绝加载 v1 检查点并自动重训。
- `learned_files`（`models/hdc_point_level.json`）是全局的，**不同模型路径不要共用同一个 learned_files**；测试时建议 `--force-retrain`。

| 优先级 | 问题 | 影响 | 建议 |

| P1 | 编码仍是"窗内 z-score + Level" | 未利用时频/AR/TOF | 按 EWSHM 2026 方案加特征工程，再做联合编码 |

| P2 | `calculate_metrics` 只算二值 | 多类信息丢失 | 增加 per-class P/R/F1、混淆矩阵 |
