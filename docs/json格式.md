1.	声明
此数据格式要求是一种交换格式，是将不同型号仪器生成的B显数据转换成统一的数据结构，主要遵循以下原则：
	不对现场仪器进行升级改造，只对现有已经在铁路应用的数据进行转换；
	可读性强，采用标准专业词语命名和十进制数值表达各种参数；
	具有扩展性，为未来可能出现的新信息预留位置；
	尽量减小输出数据量的大小；
2.	数据交换格式
数据交换的代码格式采用JSON格式。JSON的全称为JavaScript Object Notation，是基于ECMAScript（欧洲计算机协会制定的js规范）的一个子集，采用完全独立于语言的文本格式，但是也使用了类似于C语言家族的习惯（包括C, C++, C#, Java, JavaScript, Perl, Python等），在各种开发工具软件中都有类库可以调用。这些特性使JSON易于人阅读和编写，同时也易于机器解析和生成，成为理想的数据交换语言。
将钢轨探伤作业中每一次的数据、参数、信息的生成和变化都视为一次事件，每一次事件对应一个JSON对象。
事件类型包括：
1.	间隔编码；
2.	第一B显点；
3.	第二B显点；
4.	轨底波；
5.	通道参数；
6.	轨型切换；
7.	作业信息；
8.	里程位置；
9.	现场标记；
10.	倒车操作；
每种数据类型具体的含义和JSON表示方法如下文所示。
2.1.	间隔编码
B显数据是探伤仪移动等距离间隔生成的。此间隔对应《双轨式钢轨超声波探伤仪暂行技术条件》中，6.4.6要求的“应保证在最高持续检测速度下，每个探头（晶片）超声脉冲发射距离间隔不大于3mm”，和7.3.5要求的“在15km/h最高检测速度下，每个探头（晶片）超声脉冲发射距离间隔不大于3mm，即在双轨探伤仪沿钢轨纵向移动3mm的时间内，超声仪器所有通道均至少工作一次。”
对每次间隔进行编码，再将其他事件与一系列间隔编码根据先后顺序记录，是整个交换文件的总体结构，示意图如下：
 
图 文件结构示意图
一次间隔编码事件包括键名E和编码。一个文件起始编码为0，之后B显生成都计数累积。
例如第100个间隔编码，用JSON格式表示为：
{"E":1}
2.2.	第一B显点
（解释：因为B显图像是有由A显信号转换而来，并且探伤采用反射式报警，所以A显信号分析多针对超过报警阈值的第一根最高波，只有在孔裂等端角反射的时候才分析双波信号，所以对于一条A显信号最多只分析两根超过报警阈值的信号，与之对应的B显点最多记录两个。）
B显图像是有由A显波形转换而来，A显波形在大闸门内超过大闸门阈值（反射报警阈值）的信号视为反射报警信号。在A显中，从左至右第一个反射报警信号的最高点或者其上升沿与阈值线交点对应的B显点定义为第一B显点，如下图所示。由于报警信号上升沿的陡峭特性，可将最高点深度等同于上升沿与阈值线交点深度。如果报警信号是饱和状态，则其最高点深度为达到饱和状态的第一个点的深度。

2.3.	第二B显点
有些特殊伤损会在A显中产生双波报警信号，例如螺孔孔裂，此时如果将第二根回波也转换成B显，会增强伤损显示效果，因此有必要记录下来同一个间隔编码下的第二个报警信号。不同报警信号区分标准是之间波形低于穿透报警阈值，如下图所示。
 
图 双波报警信号示意图
第二报警信号对应的B显点定义为第二B显点，其深度值与幅度值分析方法同第一B显点。深度值数值范围为0~1000，单位为mm。幅度值范围为0~100，单位为%，如果原始记录中无幅度值，则视信号幅度为100%。
例如右股前直37°通道存在深度为125mm幅度为80%的第一报警信号，在深度为130mm幅度75%的第二报警信号，用JSON格式表示为：
{"B1":[7,125,80]}
{"B2":[7,130,75]}
如无第二报警信号，则不转换此事件。
（理论上A显波形还存在第三或者更多报警信号，但做伤损分析时没有必要考虑）
2.4.	轨底波
轨底波是0°通道发射超声波至轨底形成的特殊A显回波信号，本身不参与反射报警。如果小闸门2（轨底闸门）中存在高于穿透报警阈值的信号，则视为有轨底波，反之视为轨底失波。
如果仪器可以记录轨底波深度幅度，则将其视为普通B显点，如实记录信息，例如右股0°通道存在深度为176mm幅度为80%的轨底波，用JSON格式表示为：
{"B1":[9,176,80]}
例如右股0°通道存在深度为120mm幅度为100%的信号波和深度为176mm幅度为80%的轨底波，用JSON格式表示为：
{"B1":[9,120,100]}
{"B2":[9,176,80]}
如果仪器只能记录是否失波，则将轨底波视为深度等轨高幅度为100%的理想信号，例如在60轨下，左股0°通道只存在轨底波，用JSON格式表示为：
{"B1":[109,176,100]}
如果出现轨底失波情况，则此间隔编码下无轨底波事件。

2.10.	倒车
现场仪器倒车时，。倒车有两种情形：一种是在重点或者疑似位置往复倒车复核，如果全部记录每次前进的数据，会导致生成很多数据碎片；另一种是转移设备，导致长距离倒车。对于小于等于2米的倒车，视为倒车复核，B显数据只保留最后一次完整数据，即新数据覆盖同一位置的旧数据。对于大于2米的倒车，视为设备转移，倒车起始点2米之前的B显数据应保留在全程记录中，即新数据与旧数据共存。
现场仪器出现倒车，不生成编码间隔、B显点和任何事件，待重新前进时首先生成倒车事件，再正常生成数据。倒车并包含键名Back和键值表示倒车距离，单位m，用JSON格式表示为：
{"Back":1.05}
2.11.	标注
如数据在回放分析后已经被分析员标注，应将标注同时转换，标注键名Remark和字符串键值，用JSON格式表示为：
{"Remark":"无伤"}
2.12.	开关机
现场的开机、复位、睡眠等操作需要记录的同时要重新加载所有作业信息和系统参数，作为后面数据分析最新依据。
正常关机操作需要在数据中体现，方便异常关机对数据的影响。
