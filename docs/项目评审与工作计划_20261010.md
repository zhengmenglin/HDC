项目**不是"算法不work"，而是三件事叠在一起**，把输出压成了全零：

- `L348` 位于 `_train_multi_channel_ridge()`；
- ⇒ **多通道首跑（模型不存在）能存下模型，但第二次运行必然在 load 处崩溃**。

### 2.2 数据层：训练集标注几乎为空

实测 `data/train/170921_16229片段.xxc_hdc.csv`：1451 行，滑窗后 1324 个样本。

| 文件 | label_6 | label_7 | label_8 | 合计 |
|------|--------:|--------:|--------:|-----:|
| train/170921_16229 | — | — | 8 | 8 |

| test/180123_17113 | **46** | **52** | 61 | 159 |

⇒ **训练集在通道 6、7 上正样本为 0，而测试集有 46+52=98 个**。这批必然全漏，且模型在这两个通道上从未学习。

### 2.3 模型层：178/180 个类原型是零向量

```
$ 9 个通道 × 20 类原型的 L2 范数
通道 0~7 : 非零原型 0/20    ← 全零
通道 8   : 非零原型 2/20  →  class 0 (范数 1.000)、class 13 (范数 1.000)
全模型全零原型总数: 178 / 180
```

### 2.4 算法层：为什么它们永远是零

`torchhd/models.py` L133-150：

```python
def add_online(self, input, target, lr=1.0):
    logit = self(input)
    pred = logit.argmax(1)
    is_wrong = target != pred
    if is_wrong.sum().item() == 0:
        return                    # ← 整批全对，整体跳过
    ...
```

`torchhd/models.py` L94-95：`reset_parameters()` → `init.zeros_(self.weight)`（**零初始化**）。

**死锁链条**：
1. 权重全 0 → `cosine_similarity(输入, 0)` = 0 → `argmax` 恒为 0（正常类）
2. 训练样本 target 也全是 0（通道 0~7 无正样本）→ `is_wrong` 全 False
3. 命中 `L149 return`，**该 batch 完全不更新**
4. 权重保持全 0 → 回到第 1 步

**这不是参数没调好，是不会收敛的结构性死锁。**

### 2.5 判据层：严格大于零

`hdc_point_level_classifier.py` L490（多通道）/ `test_hdc_unified.py` L417（单通道）语义相同：

```python
is_defect = (max_defect_sim > threshold) & (max_defect_sim > (normal_sim + margin))
```

当前 config：`predict_threshold = 0.0`、`predict_margin = 0.000`。

- 通道 0~7：`max_defect_sim = 0.0`，`0.0 > 0.0` → **False**
- 通道 8（真值点 row=913 实测）：
  ```
  normal_sim = 0.9057,  max_defect_sim = 0.0674
  0.0674 > 0.0        → True
  0.0674 > 0.9057 + 0 → False      ← 卡在这里
  ```

### 2.6 历史数据口径对照（解释 93 这个数字）

`HDC 训练集评估报告` 显示 `Total True: 93`。实测口径反推：

- 若只统计 label_8：train 8 + test (8+8+8+61) = **93** ✓
- 若统计全部 9 个通道：train 8 + test (24+159) = **191**

⇒ 那三份报告（08:42/09:13/09:14）是 **`channels=[8]` 单通道**模式下产出的。
而当前 `config.py`（02-14 09:17 修改）已是 `[0,1,2,3,4,5,6,7,8]`。

**⚠️ 这意味着历史指标与当前配置不可比**——换通道配置会静默改变 `Total True` 这个分母。

## 五、需要决策的开放问题

1. **`docs/wenti.md` 全文只有一行「0°失波是为什么」**——实测 channel_8（俯仰 0°）非零率 73.9%、1073 个 B1 条目，是其余通道的 20~30 倍。需要确认这里说的"失波"具体指什么现象：是底波丢失、还是该通道在某个深度段没有回波？**这直接决定阶段 2-5 怎么做。**

2. **训练数据能恢复到什么程度？** `data/1/hdc_point_level_9ch.json` 显示历史上训练过 32 个文件，`data/tra 副本/` 还有一批带预测结果的历史数据。这些是否全部可用、标注质量如何，需要老大确认。

3. **要 Precision 还是要 Recall？** 钢轨探伤的安全取向通常是"宁可误报不可漏报"，但当前 `margin` 判据的设计方向反而是压 Recall。这需要业务侧给一个明确目标（例如 Recall ≥ 0.95 前提下最大化 Precision）。
