# 修复标注管理中的多余标注问题

## 问题分析
通过分析代码，我发现了导致"多了很多并没有保存的标注"问题的几个关键原因：

1. **标注列表更新逻辑问题**：每次更新标注列表时，都会重新加载标注文件，导致未保存的标注被丢弃
2. **标注保存后清空问题**：保存标注成功后会清空内存中的标注列表，导致后续操作使用空列表
3. **标注加载逻辑问题**：加载标注时会直接替换整个标注列表，而不是合并或保留未保存标注
4. **保存后UI更新不一致**：保存标注后，标注列表会重新加载，但B显图像使用的是清空后的标注列表

## 解决方案
修改以下几个关键方法，确保标注管理的逻辑正确性：

1. **修改`save_annotations`方法**：
   - 保存成功后不清空内存中的标注列表
   - 确保保存的标注与内存中的标注一致

2. **修改`update_annotations_list`方法**：
   - 更新标注列表时，只加载文件中的标注用于显示
   - 不替换内存中的未保存标注
   - 分离显示列表和内存标注列表

3. **修改`load_annotations`方法**：
   - 可选参数控制是否替换现有标注
   - 支持合并标注而不是直接替换

4. **修改`save_annotation_auto`方法**：
   - 保存标注后，确保B显图像使用最新的标注数据
   - 保持UI各组件显示的一致性

## 实现步骤

1. **修改`AnnotationManager.load_annotations`方法**：
   - 添加`replace`参数，控制是否替换现有标注
   - 当`replace=False`时，合并新标注到现有标注中
   - 确保标注ID唯一性

2. **修改`AnnotationManager.save_annotations`方法**：
   - 保存成功后不清空`self.annotations`列表
   - 确保保存的标注包含所有新创建的标注

3. **修改`MainWindow.update_annotations_list`方法**：
   - 加载标注文件时使用临时管理器，避免影响内存中的未保存标注
   - 只更新UI显示，不修改内存中的标注列表

4. **修改`MainWindow.save_annotation_auto`方法**：
   - 保存标注后，确保B显图像使用最新的标注数据
   - 保持UI各组件显示的一致性

## 预期效果
- 未保存的标注不会在刷新列表时丢失
- 保存标注后，B显图像和标注列表显示一致
- 不会出现多余的未保存标注
- 标注管理逻辑更加清晰和可靠

这个修复计划将解决标注管理中的不一致问题，确保用户创建的标注能够正确保存和显示，同时避免出现多余的未保存标注。
